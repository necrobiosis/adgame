# 末日生存 · 尸潮防线

把手游广告里那个"看起来很好玩但其实不存在"的玩法，做成一个真正能玩、有策略深度的游戏。

竖屏 9:16、中文界面、three.js WebGL 3D，5 个关卡 + 永久升级商店。
**不依赖任何外部模型或贴图资源** —— 所有几何体、材质、音效都是程序化生成的。

## 跑起来

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 类型检查 + 生产构建
npm run test     # 模拟层单元测试
```

## 怎么玩

左右**拖动屏幕**移动方阵，射击是自动的。

每隔一段路会遇到一组**二选一的门**。门面上写着它给什么（`+26 士兵`、`武器升级 +1 级`、
`后排改装 6 门大炮`…），门顶的铭牌写着**走这条车道会遇到什么怪**：

- **蜂群** —— 几百只小僵尸。要靠大炮的溅射，或者纯人海去扛。
- **精英** —— 几只巨型怪，单体血厚、一巴掌横扫一整排。要靠武器等级的单体高伤。

拿错工具走错路会滚雪球式崩盘，这就是这个游戏真正的策略层。

### 核心规则：堆人头买生存，换武器买输出

前几排士兵有清晰射界，再往后就只能从人缝里打，**每往后一排火力效率递减**。
所以士兵数量主要买的是生存能力（血条和接触面），真正的输出增长来自武器等级。
大炮不吃这个衰减（炮弹是抛射的）—— 这也正是它站在最后排的理由。

前期兵少时先堆人头，兵力起来之后转去堆火力，是这个游戏想教会玩家的那条线。

### 其它

- 路上会有写着大数字的**装甲方块**挡路。方块是装甲的，必须凑近才打得动；
  全宽的方块会逼停方阵，但两侧留了路肩缝，僵尸会从缝里挤进来 —— 一边啃方块一边挨揍。
- 每关结尾是 **Boss 战**：三阶段，会召唤尸潮、放带预警圈的践踏 AoE、直线冲锋。
  地上的红圈亮起来之前把方阵拖出去。打太久 Boss 会狂暴，所以不会耗成僵局。
- 通关和击杀拿到的金币进**兵工厂**做永久升级，存在 `localStorage`。
  后期关卡光靠人头打不动 Boss，必须把「制式装备」（起始武器等级）提上来。

## 美术是怎么做出来的

仓库里没有任何模型或贴图文件 —— 桥梁、大炮、僵尸、士兵、装甲方块全部是代码在
运行时生成的。为此有一套自己的工具链：

**几何**（`src/render/geom/`）
- `hardSurface.ts` 提供带倒角的硬表面原语：圆角盒、切角盒、工字钢（挤出 I 字截面，
  腹板与翼缘交界带圆角）、带倒角钢板、六角螺栓与螺栓阵列、法兰、车削件、管线、
  百叶口，以及**变截面放样** —— 截面用超椭圆参数化，一个参数就能在"圆角方管"和
  "圆管"之间连续过渡，角色的四肢和炮管都靠它。
- `deform.ts` 负责收尾：按折角阈值重算法线（倒角平滑、面板缝保留硬边），
  再把**环境光遮蔽**和**边缘磨损**烘进 `aSurf` 顶点属性。AO 走体素近似
  （几十毫秒烘完一个资产），磨损按顶点凸度算 —— 棱上自然掉漆露金属。

**材质**（`src/render/mat/`）
用 canvas 现算高度/法线/脏污/划痕，再经 `onBeforeCompile` 注入**三平面映射**。
合并出来的程序化几何体 UV 是废的，三平面直接用位置坐标从三个方向投影采样，
绕开展 UV 这件事 —— 没有它，程序化资产根本贴不上细节。

**角色动画**
每顶点绑两根骨骼、在顶点着色器里做权重混合，所以一种敌人仍然只要一次 draw call，
几百个角色的步伐还各不相同。阴影有配套的深度材质跑同一套蒙皮变换。

**画质档位**
低 / 中 / 高三档，影响角色分段数、配件细节、同屏实例数、阴影分辨率和环境细节密度。
开局按硬件猜一档，再用实测帧时修正；主菜单右上角可以手动切。
实测每帧三角形（含阴影通道，第五关最坏情况）：低 ≈ 40 万，中 ≈ 120 万，高 ≈ 400 万。

## 代码结构

```
src/
├── config/       balance.ts（所有可调数值）、levels.ts（5 关的赛道编排）
├── sim/          纯逻辑，零 three.js 依赖 —— 可以脱离浏览器单测
├── render/       three.js 渲染层，只读模拟状态
│   ├── geom/     硬表面几何原语与顶点烘焙
│   ├── mat/      程序化贴图与三平面 PBR 材质
│   └── units/    角色骨架、蒙皮材质、程序化人形与道具
├── ui/           DOM 覆盖层：HUD、菜单、商店、结算
├── core/         主循环、输入、程序化音效
└── meta/         localStorage 存档
tools/            开发期的 Playwright 截图脚本（见 tools/README.md）
```

`sim/` 与 `render/` 严格分离是这套设计的骨架：数值和平衡可以脱离浏览器单测，
渲染层只读不写。`tests/sim/balance.test.ts` 锁住难度曲线 —— 满配每关都打得通，
裸配打不过后三关，任何配置都会在合理时间内分出胜负。

调平衡只改 `src/config/balance.ts` 和 `src/config/levels.ts` 这两个文件。
